# 家庭厨房前端联调设计

依据用户已授权的项目完善目标和 WorkBuddy 提供的最终 RPC 协议，在当前小程序上补齐前端行为。云端部署由用户在 WorkBuddy 中执行，本地不持有管理员凭证。

## 已确定规则

- 私密厨房只允许拥有者和共有人访问；暂无访客角色。
- 订单创建、回执、接单、拒单、出餐、撤单全部走 RPC；仅 pending 可拒绝或撤销。
- cancelled 保留记录；每个用户只能读取和标记自己的 notifications。
- 提醒仅在小程序内展示，平台不具备微信订阅消息发送能力。

## 本次前端行为

- 确认点菜页增加就餐日期，默认今天；日期不得早于今天。未来日期不能使用“尽快”，切换为时间点。时间段结束必须晚于开始；不支持跨午夜时间段。临近午夜的默认时间携带正确的次日日期。
- p_order_date 表示就餐日期，所有订单卡片、详情和复制清单都显示日期与时间。
- 提醒显示真实未读总数、最新提醒和加载更多。打开单条提醒标记该条；全部已读调用全量标记 RPC，不受当前显示条数限制。失败保留未读状态并可重试。
- 自定义订单标签显示未读徽标，标签、订单列表与详情仅在可见时每 20 秒刷新。重叠请求合并，操作处理中暂停自动刷新，隐藏后不启动新请求。
- 厨房待处理数量默认包含所有日期的 pending 订单，避免遗漏预约单。
- cancelled/rejected 的进度和提示明确终止，不显示等待出餐。

## 验证与交付

使用 Node 内置测试运行器，对真实日期函数、API 边界以及用微信页面测试宿主执行的页面方法做测试；无需新增生产依赖。检查 JS/JSON 和页面事件绑定。未持有微信真机身份，实际 RLS、事务和消息落库仍须由 WorkBuddy 与微信开发者工具验证。
