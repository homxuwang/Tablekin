# 当前页排序与删除数字验证

用户要求在厨房管理当前页面内调整菜品/分类顺序，名称可见；删除增加输入数字验证。本轮按该明确要求执行，不另行请求设计确认。

## 已实现

- manage 原位置展开共用内联模板，沿用当前 records/name，固定滚动区域520rpx；名称独占一行、显式字号/颜色，操作按钮放到第二行。
- utils/inline-sort.js 处理草稿、长按测量/拖动、边缘自动滚动、置顶/置底、保存及取消。只打开一组，调整期间不允许添加/删除分类和编辑菜品。保存失败保留草稿，后台回来不自动覆盖。
- 保存沿用 reorder_kitchen_items，不新增云端协议。只有保存成功才替换管理页列表；取消还原原显示。未部署该RPC时仍明确提示待上线。
- utils/confirm-delete.js 先显示删除影响，继续后在第二个弹窗标题显示随机四位数字，精确匹配才放行；输错/取消不发送删除请求。数字不作为输入框默认内容。
- 菜品、分类、食材、厨房的持久化删除均接入验证并持有忙锁。图片移除属于编辑草稿，不删除存储文件。

## 验证边界

测试覆盖内联展开不导航、名称保留、取消不改原列表、排序保存互斥、失败保留草稿、拖动及取消清理、删除输入错误/取消拦截、正确数字放行及删除在途互斥。需微信真机核对模板显示、触摸和数字输入体验；未执行真实云端写入。
